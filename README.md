# 猫猫小窝 · 猫猫判官

暖色猫咪养成网站。支持喂食、摸摸、逗猫、休息、改名和双人养猫；首页左下角的「猫猫判官」进入独立审理界面。

## 本地运行

需要 Node.js 22（最低 22.13）。

```sh
npm ci
cp .env.example .env
# 在本机编辑 .env，填入 OPENAI_API_KEY
npm run dev
```

打开终端显示的 `http://localhost:5173`。此命令同时启动前端和 8787 端口的审理服务，Vite 自动转发 `/api` 请求。手机与电脑在同一 Wi-Fi 时，可以使用终端显示的 Network 地址。

不填 API 密钥也可以创建案件、邀请对方、选择角色、上传截图和提交陈词；双方提交后会明确显示「判官尚未连接」，不会生成假判词。配置密钥并重启服务后，可在原案件重试。

```sh
npm test
npm run build
npm start
```

生产模式由 Node 同时托管 `dist/` 和审理 API，默认地址 `http://localhost:8787`。只有前端预览时可用 `npm run dev:client`；单独启动审理服务可用 `npm run dev:server`。

## 3D 小猫与互动模式

小窝中的小猫采用本地 Three.js 三维模型，支持呼吸、眨眼、转头、耳朵微动和摆尾。摸摸会眯眼蹭蹭，逗猫会追玩具并抬爪，喂食会低头咀嚼，休息会趴下闭眼；横向滑动可以旋转观看。

直接点击小猫即可互动，也可使用两侧的摸摸、逗猫和休息按钮。每次明确点击只提交一次原有互动，继续通过同一条云存档与双人同步链路；点击小猫时会根据当前状态与可用次数选择动作，低活力优先休息，睡着后再点击可叫醒。

待机动作不会写入云存档。模型以 30 帧/秒为上限，页面隐藏或打开普通弹窗时暂停；喂食抽屉保留上方小猫的待机动作。尊重系统「减少动态效果」设置，WebGL 无法使用时保留可交互的小猫插画。

点击首页右上角「沉浸陪伴」，房间会铺满当前屏幕，隐藏资源、状态、导航、成长气泡和所有提示。小猫继续待机、互动与旋转，点击仍沿用照顾限制和原有存档流程。退出按钮与操作说明会在 3.5 秒后淡出；轻点房间空白处可再次显示，点击「退出沉浸」或按 Esc 恢复界面，键盘 Tab 也能找到退出按钮。沉浸模式只在本次打开时生效。

升级所需成长随等级逐步增加：Lv.1 → Lv.2 需要 120 点，随后为 150、180、210、240……，每级增加 30 点。成长条显示本级已获得的成长与本次升级所需成长；累计经验保留，并按新门槛计算等级。领取气泡超出本次升级门槛的经验会继续计入下一等级。

## 猫猫图鉴与成就庭院

首页右下角的「猫猫图鉴」使用猫猫素材作入口，角标显示已入住数量。打开后可以查看 12 只猫猫的图鉴、性格、邀请条件和陪伴成就；选中图鉴或成就会带到对应详情，点击「邀请加入庭院」才正式入住。未达成的猫猫显示剪影和实时进度。邀请免费，不增加经验、不扣猫爪币、不消耗照顾次数。

除第一位见面礼猫友外，邀请条件包括实际完成喂食、摸摸、玩耍、入睡，喂过不同食物、完成双人喂养，以及领取成长后达到指定等级。累计计数只随成功保存的照顾操作增长；冷却或次数不足的请求、叫醒、改名、换装和重复请求不会增加成就。旧存档会从仍可核对的日记、照顾次数与餐食记录补入已知进度，不虚构已丢失的历史；迁移后独立保存累计成就，不受午夜重置和日记长度限制影响。

已邀请的猫猫会出现在独立庭院中，按参考图在家具上蜷睡、趴卧、探头、抓柱、玩球、吃饭或伸懒腰，并配有对应的轻微动作。图鉴头像保留像素图集，场景猫使用独立的圆润手绘姿势。默认开放日式庭院，邀请 3 位猫友解锁西部露台，邀请 6 位猫友解锁暖暖雪庭；场景偏好保存在本机，入住记录属于共享小窝。三种场景使用提供的图片整理为空白背景，猫猫从透明图集单独渲染，画面里的每一只访客都对应真实的入住记录。素材与处理提示词见 [猫猫图鉴素材说明](docs/assets/catbook.md)。

图鉴沿用现有浏览器存档与 GitHub 云存档链路。配置云端时，服务器校验成就并提交存档后才确认入住，双人同时邀请同一猫猫只保存一次；永久邀请回执防止重试或短期操作日志滚动后重复加入。未配置云端的本机预览只保存到当前浏览器。发布此功能需同时更新前端和宠物 API，以支持新的 `invite-cat` 操作和可选的 `collection` 存档字段。

## 猫咪小餐桌

点击「喂食」或餐桌卡片打开蓝色底部抽屉。九种食物可按主食、零食和饮水分类，选中的食物会放大显示在餐盘上；选择只更新本机偏好，点击「喂这个」才提交一次喂食、扣除对应猫爪币并增加成长。

「双人喂养」展示两位猫友各自的食物与四小时计时。首次喂食开启四小时一轮的双人任务，两人在本轮各喂一次，额外获得一次 10 点亲密度与成长；重复喂食不会重置本轮或再次发奖。个人餐食计时与本轮任务计时分开显示。时间戳与奖励标记都保存在 GitHub 云存档，关闭页面后继续按原到期时间计算。

照顾次数由整个小窝共享，每天北京时间零点重置；冷却时间延续到次日。喂食每日 6 次、每人间隔 4 小时，九种食物共用次数；摸摸每日 20 次、间隔 5 分钟；逗猫每日 10 次、间隔 30 分钟；休息奖励每日 3 次、间隔 4 小时；双人喂养奖励每日最多 3 次。叫醒不增加成长或活力，不消耗休息次数。页面显示剩余次数和实时倒计时，云端在提交存档前再次校验限制；刷新、切换身份或重试已完成的请求不会额外发奖。额度不足或冷却中的请求不扣币、不修改小猫状态。

养猫身份采用本机持久 ID，同浏览器多标签算作同一位猫友；关闭并重新打开同一浏览器可恢复个人喂养归属。换设备会成为新的猫友，已在计时的两位猫友记录继续保留。食物素材使用统一的透明 3D 图集，生成与格式说明见 [素材说明](docs/assets/food-atlas.md)。

## 猫猫判官

1. 点击小窝左下角「猫猫判官」，发起审理。
2. 双方打开同一个案件邀请链接，分别选择 A 方和 B 方；同一角色只能由一人认领。
3. 填写经过、感受、诉求，上传截图作为证据。对方可以看到在线与正在输入状态；未提交的草稿保留在自己的设备。
4. 每轮双方都提交后才启动一次审理。判官参考双方证词和截图，说明事实、证据局限、责任、修复行动及避免重演的约定。
5. 对判词有异议时可以继续陈词、补充证据。复审同样等待双方提交，结合之前每一轮证据和判词重新判断，并保留历史记录。

新判词采用正式裁定卡片：本轮结论与把握程度、争执根因、带来源的事实和争议、蓝粉双方行为责任、猫猫判令，以及可直接使用的沟通话术。责任以「主要责任、需要改进、证据不足」等有依据的判断呈现；不会生成无法核对的责任百分比或感情温度。旧版文字判词继续完整保留。

每轮判词可附三项修复约定。双方分别确认自己实际完成的内容，只有一项同时得到双方确认才计入修复进度；可以撤回自己的确认，不能代替对方确认。确认操作只保存记录，不再次调用 AI。复议生成新的计划，旧轮任务及有效确认保留为只读历史。涉及安全边界的判词只显示自主保护建议，不开启共同确认进度，也不要求身体接触或和好。进度表示共同确认的任务数，不代表关系好坏或事实已经被独立验证。

判官语气公正、温柔，带一点猫猫的可爱。不会为了和气强行各打五十大板，也不会将片段截图当成完整事实；遇到威胁和暴力时优先保护当事人，避免强迫和好。

模型默认 `gpt-6-astra`，推理强度固定为 `high`，使用 OpenAI Responses API；支持图片输入。可以在服务端设置 `OPENAI_MODEL`。模型能力与参数参考 [OpenAI 模型文档](https://developers.openai.com/api/docs/models) 和 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)。截图及已提交证词会发送给 OpenAI 进行分析，API 使用 `store: false`。

新版通过 Responses 的 `text.format` 请求结构化判词，服务端校验字段后生成展示内容和修复任务；格式说明见 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)。不完整或无效的结构不产生修复计划。当前持久化及判词优化改动尚未进行合并后的统一验收，也未部署。

## 存档和同步

- **养猫云存档**由 Render 服务写入私有 `stevencheninfilm/cat-nest-data` 仓库，每次成功互动先提交 GitHub，再确认保存并用 SSE 同步给两位猫友。关闭网页后，使用同一猫窝链接会恢复云端进度；请收藏链接以便跨设备找回。失败的待保存操作保留在本机并自动重试，界面明确显示保存状态。未配置 `VITE_API_URL` 的本机预览保留浏览器存档与 PeerJS 演示，不能宣称已云端保存。完整配置见 [宠物云存档说明](README-pet-cloud.md)。
- **审理案件**在配置服务端 `COURT_DATABASE_URL` 后保存到独立 PostgreSQL 数据库，包括双方角色凭据的哈希、已提交证词、实际上传的图片字节、历轮判词及复议记录。每个案件在事务内锁定并保存，数据库提交成功后才向双方确认；服务重启或重新部署后从同一数据库读取。数据库故障时明确返回失败，不回退到临时文件。未配置数据库的本机开发继续使用 `COURT_DATA_FILE`（默认 `.cat-court/rooms.json`），仅支持单进程。正式环境应设 `COURT_REQUIRE_DURABLE_STORAGE=true`，避免误用临时目录。迁移和备份操作见 [案件持久化说明](docs/court-persistence.md)。
- **角色凭据**保存在当前浏览器标签页的 sessionStorage。刷新可继续使用原角色；请勿清除此案件的浏览器会话数据，清除后不能仅凭昵称重新领取已占用角色。
- **输入状态**经服务器同步；双方无需同时在线提交。提交后的陈词和证据不可直接覆盖，补充内容进入下一轮，便于核对审理依据。
- 案件邀请允许对方认领空闲角色；已认领角色的凭据用于保护案件内容和提交权限。不要公开案件链接或角色凭据。当前版本没有账户系统、角色找回或自动清理服务端案件。

## 部署

### 前端和 API 一起部署

适合支持 Node.js 22 的服务器或容器平台。设置服务端 `OPENAI_API_KEY`、`COURT_DATABASE_URL` 和 `COURT_REQUIRE_DURABLE_STORAGE=true`，运行 `npm ci --include=dev && npm run build`，启动命令 `npm start`。平台应提供 HTTPS，端口由 `PORT` 指定。切换到数据库前先导出并迁移旧实例的案件；不要在迁移前重新部署临时文件服务。Render 免费数据库30天后到期，长期存档需要无此到期限制的数据库。

项目也包含 Dockerfile：

```sh
docker build -t cat-nest .
docker run -p 8787:8787 --env-file .env -v cat-court:/data -e COURT_DATA_FILE=/data/rooms.json cat-nest
```

API 密钥只通过服务器环境变量传入。不要使用 `VITE_OPENAI_API_KEY`，也不要把 `.env`、案件文件或备份放入公开仓库。

容器可传入相同的 PostgreSQL 环境变量；上述命名卷示例仅用于单实例文件存储。数据库与服务代码的部署周期独立，保留数据库并定期备份。案件持久化变更目前等待合并后的统一验收；待测项目见 [验收清单](docs/court-persistence-acceptance.md)。

### 保留 GitHub Pages

现有仓库目标为 `stevencheninfilm/cat-nest`，`.github/workflows/deploy.yml` 会测试、构建并部署 `dist/`。GitHub Pages 运行静态前端，Render 的 `https://cat-nest-api.onrender.com` 提供宠物云存档与判官 API。GitHub 写入凭证只保存在 Render 的服务器环境变量。

1. Render 运行 `node server/index.mjs`，设置 `GITHUB_TOKEN`（仅私有数据仓库 Contents 读写）、`GITHUB_REPOSITORY`。宠物进度保存在 GitHub，不依赖 Render 的临时磁盘。
2. 在 GitHub 仓库 **Settings → Secrets and variables → Actions → Variables** 设置 `VITE_API_URL` 与 `VITE_COURT_API_URL` 为 `https://cat-nest-api.onrender.com`。
3. 在 API 服务器设置 `CORS_ORIGIN` 与 `COURT_ALLOWED_ORIGINS` 为前端的确切 origin，例如 `https://stevencheninfilm.github.io`；多个 origin 用逗号分隔，不包含路径、不使用通配符。
4. 重新运行 Pages 工作流。前端会连接此 API；同源部署无需上述两项配置。

没有配置可访问的判官服务时，已部署的静态网站会保留养猫功能，并明确提示判官服务未连接。

## 验证范围

`npm test` 包括养猫状态、GitHub 存档并发合并/失败恢复、SSE 双人同步、客户端确认保存队列、PeerJS 演示同步、判官角色权限、双方提交门槛、截图输入、并发审理、复审上下文和存档恢复。判官接口测试使用隔离的模拟 OpenAI 响应验证调用协议，不替代配置真实 API 密钥后的端到端验收。
