# 厨房终端与教材整理

厨房视角只保留场景与操作入口。原场景下方的「厨房实时工序」及底部「当前制作流程」均已移除，释放出的高度由场景填满。

打开右上角终端，展开「单菜测试」，可单独迎接一份暖暖蛋包饭或猫爪拿铁订单。该操作暂停自然来客；订单选择器仅显示有详细厨房工序的订单。摘要保留菜名、当前步骤、员工、工位及进度，接单和下一道工序需明确点击。状态刷新不会推进尚未点击的工序，也不会自动送餐。餐桌满时先结账或在员工测试中切换预设。

终端顶排的「重播」已改为「重置」。在测试存档点击后立即移除场景顾客、清空全部订单和工位流程，并暂停自然来客。餐厅保持空场，直到点击「单菜测试」里的菜品，再迎接一位点这道菜的顾客。重置保留员工、体力、设施、装扮、钱包、小窝成长和营业经验；重复点击不会发奖励或复用旧订单编号。断线、保存中及正式存档不能执行此测试重置。

重置补充验收：`restaurant-staff-terminal`、`restaurant-kitchen-terminal`、`restaurant-guests`、`demo`、`restaurant-staff` 共 47 项通过。覆盖繁忙全员场景重置、重复空场重置、两道菜各产生一位指定点单顾客、保存/断线拦截，以及服务端拒绝伪造的正式重置意图。

共享版本 `assets/index-B6FqhsDF.js` 浏览器实测：双人桌的 2 位顾客、2 份订单重置后立即归零；关闭终端等待 6.5 秒仍保持空场。分别选择拿铁、蛋包饭，均仅出现 1 位顾客和 1 份对应菜品订单。钱包始终为 11,960、餐厅等级保持 Lv.1。最后再次重置，展开单菜测试并保留窗口供用户操作。截图为 `artifacts/restaurant-art/screenshots/terminal-reset-empty.jpg`、`terminal-reset-coffee.jpg`、`terminal-reset-rice.jpg`。

终端的单菜区域、员工区域及日志可分别折叠，刷新状态时保留展开情况、滚动位置与选择。点击终端接单或开始工序后保持终端打开；操作来源在刷新按钮 DOM 前记录，避免刷新后丢失所属终端的判断。

点击终端底部「玩法与教材 →」，工序教材位于说明末尾。两道菜的工序按顺序列出，独立折叠；正常营业不再显示这些后台摘要。

屏幕宽度至少 968 px 时，游戏保持 480 px 宽，终端固定在右侧外部空位，距屏幕右边缘 12 px，宽度不超过 264 px，并预留与游戏之间的间距。更窄屏幕使用游戏内紧凑浮窗，终端可自行滚动。

验收：975×891 时游戏右边界 727.5 px、终端左边界 739.5 px，无重叠。390×844 与 320×740 无横向溢出，终端分别落在 x=114…378 和 x=44…308 内。教材是说明内容最后一个区块，场景中的旧实时面板数量为 0，未发现可见破图。

`tests/restaurant-kitchen-terminal.test.mjs` 覆盖空订单、到店与制作阶段、待分配员工、下一步显式操作、订单切换、收款后选择失效、状态原位绘制及静态教材。与厨房 UI、员工终端专项合计 23 项通过。共享构建通过全部 7 个存档入口一致性检查；最终 checkpoint 为 `assets/index-CbLgRYPj.js`。浏览器复验接单和取料后终端继续打开，取料结束停在「待点击 · 清洗洋葱、青椒和胡萝卜」，等待下一次明确操作。
