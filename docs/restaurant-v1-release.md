# 猫猫餐厅 V1.0 发布记录

## 发布范围

餐厅独立经营界面、21 道菜品的 169 个工序、十个互斥工位、手动逐步操作、员工走位与排队、蓝色进度圆环、循环制作动画、员工体力与休息交接、送餐及收款、顾客图鉴与二次点单、研发抽卡、设施升级和餐厅装扮统一发布。

营业区有四首 BGM，研发区有两首独立 BGM；声音设置可分别选曲、试听、调节音量与静音。按键、制作、送餐、收款、抽卡、升级、布置与布置完成接入对应音效。

小鱼干与小窝金币共用钱包；结算增加小馆经验，并生成等额「餐厅经营经验」气泡，回小窝手动领取。既有房间、缓存空间、待保存队列和奖励去重记录继续沿用。

## 入口与权限

- 仅 `test` 存档显示并允许打开餐厅调试终端。开发模式和本机访问不会额外授权其他存档。
- 所有小窝左下角统一高亮「猫猫餐厅」；图鉴中的餐厅入口继续保留，猫猫判官移至设置。
- 九个已登记存档共用一个 `src/`、一份构建和同一发布提交；保留 Harry 与大小写敏感的 Crown 入口。
- `/cat-nest/` 继续默认进入测试版；监测后台仅供本机使用，3D 小屋继续暂未开放。

## 整理方式

1. `codex/restaurant-v1-source` 保存各聊天冻结后的源码快照。
2. `codex/restaurant-v1-release` 从最新 `main` 整合发布，保留已上线的新手指引、向导状态、水獭、版本历史与静默保存功能。
3. 共享 `5174` 预览保留给本地验收；发布工作树只运行离线测试与构建，不另开预览服务。
4. 通过测试后先推送发布分支和 PR；核对 main 提交后触发既有 Render API。Pages 发布门禁等待同一提交的后端健康，再发布前端。
5. 前后端版本、九入口一致性和线上测试版检查通过后，为已发布提交标记 `v1.0.0`。

## 检查依据

- 厨房、员工、顾客、奖励、云端队列、终端隔离及已有小窝功能参加统一回归。
- 本机排除会另开 Vite 服务的模型预览测试；该测试由 CI 的完整 `npm test` 执行。
- 构建自动检查所有登记入口的脚本一致性；API 镜像检查递归覆盖全部相对导入并在隔离目录导入处理器，不启动服务或读写存档。
- 菜品聊天已完成甜甜圈全部 12 道工序、员工交接、送餐、收款与成长领取；最终小屏按钮命中、21 行横向工序后台、图片加载和控制台验收通过。
