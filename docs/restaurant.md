# 猫猫餐厅

本地 `/test/` 小窝左下角以金色高亮「猫猫餐厅」直接进入，并可直接返回小窝；图鉴内原餐厅入口继续保留。使用手机竖屏独立画面；`#restaurant` 可以在选好身份并同步原小窝后回到餐厅。从图鉴进入时返回图鉴，从小窝进入时返回小窝。共用所有存档的同一份前端、构建和状态 reducer，不增加云端房间，不改变任何缓存前缀。3D 小屋开关保持关闭。

## 经营

- 客人从街道经过正门，约 6 秒后入座并开始制作订单；30% 概率两位朋友共用一桌，左右两座各点一道菜。普通料理制作完成后点击送餐，蛋包饭与拿铁按厨房完整工序自动送达；客人用餐 4.5 秒后可以收款。
- 共 18 道普通料理和 3 道金色招牌，菜谱支持按类别筛选。小馆独立积攒营业经验，与主猫猫共用首次升级 120、以后每级增加 30 的阶梯；当前资源分布在 Lv.1–50 开放，等级继续提升。详见[成长与资源路线](restaurant-progression.md)。
- 厨房升级加快制作；座位可从 2 桌扩至 8 桌；暖心服务增加小鱼干收入；每道菜可以研发到 4 级。
- 可雇佣 6 位猫员工，连同基础主厨共 7 位伙伴。已接订单按接单时的设施、菜谱和员工水平结算。
- 奶油、薄荷、樱花三种装扮购买后可重复切换。
- 营业画面有空桌时约每 9 秒自然来一桌；打开面板或离开页面时不再迎接新客，已接订单继续计时，收益须手动收取。

餐厅显示的“小鱼干”就是原小窝的 `coins` 钱包，喂食与经营共用余额；结账立即增加小馆营业经验，并按 1:1 生成标为「餐厅经营经验」的 `pendingGrowth` 气泡，回小窝点击后计入 `xp`，跨级会生成原格式的成长纪念卡。原照顾奖励保留；旧存档已入账经验不补发，未领取气泡不失效，伙伴可共同领取且只入账一次。

新存档的默认初始资金为 **100 小鱼干**，各存档入口共用 `src/game-defaults.js` 的 `INITIAL_COINS`。测试页预置喂养记录完成后也从 100 开始；已有存档按原余额加载，终端「重置」只清空顾客和订单，不补发或扣减资金。

## 数据与同步

`state.restaurant` 包含订单、菜谱研发、设施、员工、主题与经营累计。没有餐厅的旧存档只补一个空餐厅；已有六道菜的餐厅保留全部设施、员工、主题、统计、订单和研发，只为新增菜品补上 1 级研发。云端读档仅在内存中迁移，下一次经营操作再正常写入原房间。客户端只能提交经营意图；售价、制作完成时间、收入和成长由共用规则及服务端时钟计算，不能上传奖励金额。订单领取后移除，单调订单编号不复用。云端仍使用原请求队列、修订与冲突保护；同一订单无法被两位主人重复收款。收入动画在已确认存档增加时展示。

`test` 沿用浏览器临时测试存档，刷新恢复默认。正式存档须发布共用前端和带有 `restaurant.js` 的 API 后才能线上使用，尚未进行线上发布。

内置 ImageGen 生成场景、6 种角色正背面和 18 道菜。圆润版角色直接使用用户提供的两张游戏图作为 reference：短胖身体、头身一体、小四肢与粗描边。

- `public/assets/restaurant/restaurant-scene.webp`：940×1672 的餐厅环境。
- `cat-sprites.webp`：4×3 图集，每格 256px，角色正背面相邻。
- `food-sprites.webp`：原六道菜的 3×2 图集，每格 256px。
- `food-expansion-v1.webp`：新增十二道菜的 3×4 图集，每格 256px。
- [新菜图集与生图提示词](assets/restaurant-menu-expansion.md)。
- `sprites.json`：精灵坐标、脚底锚点和场景桌位。
- [完整生成提示词](assets/restaurant-prompts.md)。生成源图保存在本机忽略目录 `artifacts/restaurant-art/`。

移动使用独立 DOM 角色与 CSS 动画：真实顾客沿街道、正门、过道到达自己的椅子，结账后原路离店；员工按厨房工序走位、加工和端餐。角色节点保留，时钟从存档时间戳推导，状态刷新不会重播进场；减少动态效果时直接展示入座结果。

## 顾客控制终端

测试存档与本机预览的餐厅右上角显示「终端」。点击后在入口下方打开小浮窗，一排五个约 44px 的按钮用于单人、双人、随机来客、暂停/恢复自然来客和重播入座；桌位、顾客和未结订单以一行显示，详细记录默认收起。浮窗不遮罩或锁定餐厅，迎客、重播后保持打开，可直接观察和继续操作；入口、关闭按钮或 Escape 均可收起。客满时显示提示，不覆盖原订单。重播仅改变画面，不创建新订单或奖励。

`restaurant.parties` 将同桌成员关联到独立订单；桌位按聚会占用，两人同桌只占一张桌。先结账的客人保留座位等待伙伴，最后一单结清才释放餐桌并一起离店。旧存档按原订单生成单人桌，保留原订单时间、钱包与成长，不写入新的房间。共用服务端 action 为 `restaurant-arrive`，客户端不能提交猫咪、桌位、时间或奖励。

新增顾客测试覆盖 30% 双人概率、八张桌子的连续路径、左右座、刷新不重播、旧档迁移、分次结账及伪造关联；云端模拟覆盖双人到店重试、原房间重载和两客户端抢最后一份账单只能成功一次。

参考玩法已通过浏览器抽样观察用户提供的两段视频：从小摊扩充餐车，订单气泡、员工搬运、菜品制作时间和售价、设施与员工升级。本次实现室内小馆的完整经营循环；参考中的多地图店面、角色服饰背包和广告加速尚未加入。
