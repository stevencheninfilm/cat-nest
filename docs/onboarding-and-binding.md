# 渐进式新手引导与双人绑定

所有入口使用同一套应用和构建。新手引导由 `src/onboarding.js` 提供，测试入口只注入模拟伙伴和隔离数据，不维护另一套游戏。

## 体验

1. 选择男方或女方；邀请链接使用当前存档网址的 `?join=另一身份`，只高亮建议身份，不自动代选。
2. 新建的注册小窝可选毛色、命名并领养；已有小窝显示原猫和原名，不重新创建。名字不变时不发送改名操作。
3. 第一次摸摸（可用时也可逗猫）→看到爱心→点击领取成长；只有服务端确认后才前进，失败保留输入并允许重试。
4. 邀请第二位主人：复制当前小窝的链接或用设备分享；复制完成仍显示等待加入。邀请页明确显示两位主人的加入与在线状态，稍后邀请不会阻止继续玩。

步骤可以暂停，从设置的「一分钟新手引导」继续。已有浏览器的老主人不被强制重新引导，已有猫咪不被强制改名。引导完成/暂停和每个身份的步骤使用当前存档的 storage 适配器，Steven 原键及 Evian 原前缀不迁移、不清除。判官邀请入口不弹出养猫引导。

## 绑定及兼容

`homeBond` 是版本 1 的可选兼容字段：`{version:1, owners:[{id, joinedAt}], adoptedAt:null|时间}`，仅接受原有 `partner-male`、`partner-female` 两个角色。旧存档缺失该字段时，从已有喂养、照顾、历史及双人纪念推断已加入角色；不以在线状态或复制邀请来推断加入。后续正常保存将其持久保留，离线和历史记录滚动不解除加入状态。

`join-home` 只记录所选主人加入，不发成长、不改钱币、不消耗照顾次数、不生成伪照顾记录。`adopt-cat` 原子保存新猫名字和外观，只允许尚未养成的新猫，不能用来替换老猫或重置进度；并发的第二次领养被拒绝并同步另一位已确定的名字。两者都经过现有动作队列、GitHub CAS、去重和 SSE，不新增房间或鉴权系统。此次是现有双角色使用方式的加入记录，不加账号、密码。

首次引导只使用正常照顾和领取动作，沿用每日额度、冷却和服务端成长校验。次数耗尽时可以打招呼并继续邀请，不产生额外成长。成长跨阶段弹窗会等引导关闭后再出现。

## 测试入口

测试控制台新增「从第一次养猫开始」，只在当前测试页面生成空白演示状态，刷新仍恢复默认测试进度。共用引导内可模拟第二位主人实际加入；正式入口显示复制和设备分享。控制台「重新查看指引」调用同一个共用引导，不再叠加一大页欢迎说明。

## 验证

- 参数化邀请链接、旧记录兼容、持久加入、角色与存档缓存隔离。
- 领养不可覆盖已有猫、并发命名、动作保存失败、乐观回调不可提前推进。
- 引导完整流：命名→照顾→领取真实成长→邀请，老主人跳过强制引导。
- 共用构建检查 steven、evian、test 的 HTML 与资源完全一致。
- 发布从干净 main 做增量，只合入本功能；共享目录中世界、小窝布置、日记等未完成内容保留在原处。
