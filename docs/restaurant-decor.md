# 餐厅六套场景与猫猫施工队

2026-10-18，本地共享预览：`http://127.0.0.1:5174/cat-nest/test/index.html#restaurant`。未发布线上。

## 场景与实际属性

| 场景 | 完整套装 | 解锁后常驻增益 |
| --- | --- | --- |
| 奶油时光 | 奶油烘焙屋 | 收入 +1% |
| 奶油时光 | 暖光书房 | 成长 +1.5% |
| 薄荷假日 | 薄荷花房 | 制作速度 +1.5% |
| 薄荷假日 | 海盐假日 | 收入 +2%、制作速度 +1% |
| 樱花物语 | 樱花茶屋 | 成长 +2% |
| 樱花物语 | 花灯晚宴 | 收入 +1.5%、成长 +1% |

每套包含一张独立生成的完整场景，以及窗边、墙边、厨房三件透明道具。六套保持同一入口、六桌位置和厨房布局，兼容现有顾客走动、员工工位与订单气泡。由独立场景图片呈现美术，不使用色相滤镜替代。原用户要求的中央门梁小招牌保留。

已解锁套装的属性永久累计，无需换上对应场景；布置只改变外观。每项单套增益仍为 1–2%，全部六套解锁后合计收入 +4.5%、成长 +4.5%、制作速度 +2.5%。制作速度作用于真实加工步骤，步行时间不缩短。购买解锁成功即生效，不必等施工完成。已拥有基础主题的旧存档继续拥有对应默认套装，默认奶油场景因此有收入 +1%。

接单时用 version 2 快照冻结已解锁套装 ID、合计收益和制作速度；严格验证已知且已拥有的 ID、目录顺序及精确合计，拒绝伪造。换景、再解锁和重连不会重新定价旧订单；旧单套快照、无装扮快照订单继续保持原收益和制作时长。小额鱼干与 0.1 成长单位以下的尾数保留累计。合计只在营业信息中显示，场景中央不再常驻展示套装说明牌。

## 施工

选择一套装扮后，服务器创建一个 12 秒施工任务，同一房间同时只有一个任务。两位独立生成的圆猫施工队员，从入口走到窗边/厨房，橘猫继续走到墙边，施工后安置道具并收工离场。前后视角分别使用透明帧，行走、敲击、闪光、道具落地使用 CSS 动画。坐标按场景百分比与脚底锚点定位。

0–2 秒入场；2–7 秒施工；7、7.8、8.6 秒依次安置窗边、墙边、厨房道具；9.5–12 秒离场。7 秒之前保留旧场景外观，常驻加成始终按已解锁套装计算。真实存档重连/换身份继续同一施工时间；测试入口按既有规则刷新恢复默认。已拥有的套装免费再次布置，仍执行完整施工。

施工中暂缓自然新客，已有订单继续。控制器关闭时取消动画帧，打开后按持久化时刻恢复。减少动态效果偏好关闭摇摆、敲击和弹落动画，施工时钟不变。

## 测试终端与新增场景

餐厅右上角“终端” → “解锁全部装扮”，或全局演示控制台 → “解锁全部餐厅装扮”。由测试适配器调用专用 scenario，动态合并装扮与普通/珍藏主题目录。保留钱包、成长、当前装备、活动订单、施工和原房间，不伪造完成时间。正式存档不提供该适配器与按钮。

新增套装登记到 `RESTAURANT_DECORATIONS` 后，测试解锁会自动覆盖新 ID。美术按 `public/assets/restaurant/decor/<id>/{scene,window,wall,counter}.webp` 放置并补充 manifest，现有三模块布局即可沿用。独立新主题须同步登记主题目录；不复制应用、入口或存档代码。
