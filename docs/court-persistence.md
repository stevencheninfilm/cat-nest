当前状态：代码已统一合并，隔离自动化测试、真实 PostgreSQL 并发与备份恢复、本地模拟判官联调已通过，详见[统一集成记录](integration-2026-10-14.md)。生产数据库尚未创建，旧案件尚未迁移，尚未配置线上连接或发布；真实 AI 与生产验收仍待执行。

## 持久化范围

完成生产配置后，线上案件使用独立 Postgres 数据库。每个案件以完整 JSON 保存在 `cat_court_rooms.room` 中，包括双方姓名及角色凭据的哈希、双方证词、实际上传截图的完整 data URL、初审判词、各轮复议证词和判词、结构化分析、修复任务及双方有效确认时间、轮次状态及 revision。前端会压缩截图，本方案保留的是实际提交的图片字节。截图、文字与修复确认在案件事务里保存，不能出现“文字保存了、截图只留在服务内存”的情况。

应用实例的重启或重新部署不会替换这份数据库。在线状态、正在输入状态仍是临时信息；浏览器的角色凭据仍由原来的会话保存机制管理。数据库保留角色哈希，并不等于新增了账号登录或丢失浏览器凭据后的身份恢复功能。

数据库是运行中的存档，不代替备份。应同时启用所选数据库方案的备份，并把必要的离线备份保存到受限目录。删除数据库、免费数据库到期或人工删除案件不属于“服务重启”。不要使用会到期的免费数据库作为长期保存方案；付费资源的选择仍待用户确认。

## 生产配置

由服务端安全配置以下变量：

| 变量 | 用途 |
| --- | --- |
| `COURT_DATABASE_URL` | 判官专用 Postgres 连接；优先使用同区域、同工作区的 Render 内部连接地址。 |
| `DATABASE_URL` | 未设置 `COURT_DATABASE_URL` 时的备用连接变量。 |
| `COURT_REQUIRE_DURABLE_STORAGE=true` | 生产保护开关，防止连接缺失时退回临时 JSON 文件继续接收案件。 |
| `OPENAI_API_KEY` | 既有 AI 密钥；保持服务端 Secret File 配置，不写入前端或迁移备份。 |

外部数据库连接使用校验证书的 TLS；不要配置 `sslmode=no-verify`，也不要关闭证书校验。内部连接按服务与工具共用的连接配置处理。数据库连接失败时，应修复连接，而不是删除保护开关或临时切换回文件存储。

连接地址含数据库凭据，不能放入聊天、Git、命令行参数、截图或日志。所有环境配置应留在 Render 的服务端秘密配置中；本地 `.env` 已被 Git 忽略。迁移脚本只从上述环境变量读取数据库地址，不接受 `--database <明文地址>`。

## 先保全旧线上案件，再切换

旧版使用 Render 免费实例的临时文件保存案件。**任何重新部署、实例替换或重启前，必须先取得旧实例的完整存档。**新增 Postgres 连接不会自动把旧实例的文件复制过去。养成端聊天已报告部署了 `ce2ace2`；此前旧案件是否仍存在尚未核查，不能假定其仍可从当前实例取回。若实例已经丢弃临时档案，新数据库无法凭空恢复丢失材料。

已知迁移阻碍：旧免费实例没有可用 Shell；本地 `server/data/court.json` 不包含线上案件 `c9a6dff01066`。此前的生产测试报告只是验收记录，未包含双方角色哈希和完整私有案件对象。这些文件不能冒充旧实例的完整备份，也不能据此声称旧案已安全保留。

旧版网站的授权读取 API 是给页面显示用的，会省略部分私有字段；直接保存网页、截图或普通 API 响应不等于完整迁移。若只能通过两位已授权用户读取材料，需要另行设计恢复操作、确认身份和凭据连续性，并核对全部历史；该路径当前没有执行。取得完整旧档的办法未解决前，不重启旧实例、不删除旧文件、不先部署新存储版本。

取得完整旧档后，按以下顺序操作；这些步骤目前全部待执行：

1. 暂停双方写入，明确存档时间点，避免导出后又有新证词进入旧实例。
2. 从旧实例安全导出完整 `{ "version": 1, "rooms": { ... } }` JSON，文件权限设为 `0600`，保存在 Git 忽略的受限目录。
3. 使用 `inspect` 记录案件、轮次、双方提交、截图、判词数量和 SHA-256 摘要；确认目标案件在完整档内。
4. 创建已确认的长期 Postgres 数据库，在受信任服务端环境配置连接变量。
5. 使用 `import` 导入旧档，再使用 `export` 导出数据库快照到另一个新文件；两份档案的内容摘要和各项数量应一致。
6. 确认备份可读取、旧角色哈希保留、证据与复议完整后，配置生产保护开关并部署合并后的应用。
7. 等用户统一测试通知后，以原双方凭据验证旧案件，再验收新的案件流程和重启、重新部署场景。

遇到同编号不同内容的案件，整批导入失败并回滚。先调查两个来源的差异；不要删库、覆盖案件或修改摘要来绕过冲突。

## 离线工具

命令仅作为准备好的操作步骤；当前未执行。脚本不会调用在线判官 API、OpenAI 或自动提交证词。`inspect` 只读取本地文件；`import` 会写入指定环境变量对应的数据库，`export` 只读取数据库并新建本地文件。

从项目目录执行。路径有空格时使用引号，文件名使用新的日期和时间。以下目录 `.cat-court/` 已被 Git 忽略：

```sh
node scripts/court-archive.mjs inspect --file .cat-court/backups/legacy-before-switch.json
node scripts/court-archive.mjs import --file .cat-court/backups/legacy-before-switch.json
node scripts/court-archive.mjs export --file .cat-court/backups/postgres-after-import.json
node scripts/court-archive.mjs inspect --file .cat-court/backups/postgres-after-import.json
```

输出只包含数量、SHA-256 内容摘要及导入新增/跳过数量，不打印证词、图片、角色哈希、AI 密钥或数据库地址。底层数据库错误也不会原样输出连接信息。备份文件本身包含私人证据和角色哈希，应限制访问，不能提交到公共仓库。

导入先验证完整本地档，再打开数据库连接；所有案件在一个事务中导入。相同编号且内容摘要相同的案件可幂等跳过；同编号但内容不同则整批回滚，不覆盖任何已有案件。事务提交时若网络回应丢失，不能假定数据库未写入；应重新导出核对，必要时幂等重试。比较会忽略 JSON 对象的键顺序，但不会更改文字、图片、数组顺序、时间、未知案件字段或角色哈希。旧档缺失 `revision`、旧截图缺失 `size` 不会被迁移工具补写，从而能核对迁移前后的原始内容。

导出读取同一个数据库快照，先写入 `0600` 临时文件、刷新到磁盘，再原子创建目标文件。目标已存在时拒绝覆盖，包括同名符号链接；请使用新的文件名。文件发布或磁盘刷新失败时不会报告成功，需保留旧备份并重新检查。导出完成后可比较摘要，不能把导出到本机视作云端灾备已经落实。

## 合并后待验收

下面只记录迁移专项验收，不代表已通过。完整联调清单以项目统一验收记录为准。

- 完整旧档导入后，两方角色哈希、原证词、截图字节、初审判词、所有复议记录和 revision 无损；导出摘要与输入相同。
- 导入同一档两次不增加案件、不改变内容；同编号不同内容、损坏文件或中途数据库错误均整批回滚。
- 备份文件权限为 `0600`，已存在的文件和符号链接不会被覆盖；成功与失败日志均不包含私人内容和凭据。
- 重启、重新部署以及两实例访问后，已提交的全部材料仍可由原双方授权读取；未授权用户不能读取证词或截图。
- 仅一方已提交时重启，保持等待另一方；初审和复议完成后重启，保留各轮历史且不自动重复调用 AI。
- 判词生成中实例中断时保留双方提交材料，按明确的恢复状态处理；恢复与重试不能产生重复判词或覆盖新一轮。
- 数据库不可用、连接变量缺失或写入失败时，不返回保存成功、不退回临时存储、不触发未成功保存的 AI 请求；恢复连接后能继续。
- 备份恢复到隔离数据库后，核对原案全部内容及双方授权，再按用户通知进行真实双方提交、截图分析和复议测试。
- 新版结构化判词与修复计划一并导出和恢复：任务标识、正文、双方有效确认时间和撤回后的状态完全保留；旧版无修复任务的文字判词不被自动补写。各轮计划不相互覆盖；危险模式与任务模式不一致时归档校验失败，不把安全建议恢复成共同确认任务。
