# 状态衰减与成长加成

饱饱、开心、活力每一项严格大于 80 时增加 10% 成长。加成相加：0/1/2/3 项达标分别为 1.0/1.1/1.2/1.3 倍。80 本身不达标，不使用三个 1.1 相乘。按互动开始时、自然衰减后的状态计算；互动自身增加的状态用于下一次互动。

每 30 分钟饱饱、开心、活力各自然下降 1 点，最低为 0，离线时间也计入。存档增加可选字段 `needsUpdatedAt`，保留未满 30 分钟的时间；领取、改名、换装及频繁刷新不会重置计时或重复衰减。旧存档缺少该字段时，从原有 `updatedAt` 开始推导。客户端按存档时间显示变化，服务器在接受互动时重新计算，定时刷新不会向云端写入。

状态平衡：喂食开心 +0、摸摸开心 +1；陪玩饱饱 −1、开心 +2、活力 −2，至少 2 点活力才能陪玩；休息活力 +40，普通食物活力 +10、清清饮水活力 +12，最高 100。食物的饱饱恢复量、金币/亲密度/基础成长、每日次数及冷却不变。`src/pet-needs.js` 的 `CARE_NEED_EFFECTS` / `PLAY_ENERGY_COST` 与 `src/state.js` 的 `FOODS.energy` 是前后端规则与详情说明共同使用的数值来源。原有存档保留当前值及计时锚点，按新的每 30 分钟节奏继续自然下降，不补发状态或重置成长。

成长奖励在气泡生成时固定，并保存 `boosted:true` 与 `boostCount:1..3`。旧气泡保持原值；早期只有 `boosted:true` 的记录仍按 1.1 倍校验。奖励及累计 XP 保留一位小数，按十分之一做加法，避免摸摸等小额奖励被舍掉。示例：三项达标时摸摸 3→3.9、陪玩 8→10.4、休息 4→5.2。亲密度、金币及状态恢复量不乘算。双人喂食的额外基础成长也使用同一次互动的倍率。

领取保持原有 GitHub SHA 原子冲突重试、永久回执与 SSE 同步流程。倍率不由客户端请求提交，领取时不重新加成。数值无法安全相加时拒绝领取并完整保留气泡。后端需要随前端一起发布，以支持新奖励格式和小数经验；无需新环境变量或数据库迁移。

点击主界面的三个状态数值分别打开对应说明：显示当前值、本项贡献、总倍率、单项达到 81 点所需的提升、恢复方法、自然下降规则及互动冷却。喂食菜单与确认按钮同步展示已含当前状态加成的成长，双人额外奖励另计。

实现：`src/pet-needs.js` 为共享规则与精确加法；`src/state.js` 负责生成、领取与存档归一化；`server/github-store.mjs` 校验时钟字段和奖励。`src/pet-needs-ui.js` / `src/pet-needs.css` 为状态详情；`src/main.js` 接入点击、实时显示与恢复前台刷新；成长、阶段和喂食展示兼容小数经验。

首页倍率移至成长条右上方，使用内置 image_gen 生成的开心果绿玻璃果冻徽章，奶油色文字区与细香槟金边保持对比。运行素材为 `src/assets/growth-bonus/v1/pistachio-glass.webp`（445×128，保留透明通道，约 12 KB），完整提示词及原图路径在 `docs/growth-bonus-prompt.json`。横向三段切片保留圆润两端；成长文字 12px、实时倍率 14px，窄屏避让名字及右侧操作按钮。素材不含数字，倍率继续由原有状态规则实时计算。

徽章是可键盘操作的详情按钮；无加成时仍显示 ×1.0，便于查看提升目标。点击打开总览，列出三项的当前值、各自 +0% / +10% 贡献及总倍率，未达标行提示达到 81 点还差多少。每行可进入该状态的恢复方法，单项详情也可返回总览。打开的总览随原有状态刷新时钟更新，只有查看动作，不提交互动或存档请求。

详情页的当前倍率使用单独生成的奶油玻璃镜面 `src/assets/growth-bonus/v1/detail-lens.webp`，果冻材质为 `detail-fill.webp`。两张素材均由内置 image_gen 以原徽章为材质参考生成，完整提示词在 `docs/growth-bonus-details-prompts.json`，文字和数值仍为实时 HTML。按用户最新要求，删除总览中整块“距离 ×1.3”区域，包括三段目标进度、达标数量和快捷提升按钮；保留当前总倍率与状态贡献列表。

饱饱、开心、活力详情沿用同一套镜面、果冻进度与增量小徽章，分别以浅蜜糖、柔粉、开心果绿区分。突出实时大号数值与提升方法，移除装饰表情、英文眉题和重复的三项加成面板。食物列表保留各自恢复量及冷却；开心展示摸摸、陪玩的恢复量；活力展示休息 +40、清清饮水 +12、普通食物 +10，并提供轻量的喂食入口，即使休息次数用完或冷却中仍可进入。喂食预览同步显示所选食物的活力恢复量。饮水和食物继续共用每日 10 次喂食与原有各人冷却，休息仍为每日 3 次、间隔 4 小时；叫醒不恢复活力，拒绝、重复操作及刷新不会额外恢复。底部通过简短的总倍率入口返回成长加成总览，直接互动、冷却限制和休息中的提示继续沿用原有逻辑。

首页三项状态变化由 `src/pet-needs-feedback.js` 负责轻微反馈：数字在 320ms 内平滑到新值，数值下方以 11px、800 字重显示真实增减。提示用 100ms 淡入，清晰停留约 2 秒，再以 800ms 缓慢淡出，位移不超过 3px。连续互动时，同一状态在提示消失前的实际净变化累计成一条提示，每次更新后重新停留 2 秒再淡出，累计更新不重复淡入或闪烁；正负变化抵消后不显示 0，提示消失后的新变化重新累计，各项分别计时。提示贴近数字右侧下方，正数为深柔绿色，负数为暖棕色，显示阶段不透明度为 96%，不使用底板、粒子或发光。只比较已显示状态与新状态的实际差值，达到 100 的恢复量不会夸大；相同的乐观预览与云端确认不重复播放或延长计时。首次云端读档、回滚、后台或沉浸界面直接同步数值并清理动效与累计值。系统开启减少动态效果时，数字立即更新，增减提示静态短暂显示。

2026-10-15 再平衡：开心不再随喂食累加；三项状态统一每 30 分钟各下降 1 点，摸摸 +1、陪玩 +2；活力通过休息 +40、普通食物 +10、饮水 +12 恢复，陪玩消耗降至 2。基础成长、价格、照顾次数与冷却均保留。`NEEDS_DECAY_PER_INTERVAL` 与 `needsDecayDescription()` 共用每项衰减规则，状态详情、成长说明和主说明同步展示。保留原始存档与计时锚点，未结算的离线时间按当前规则推导，不批量改写状态或补币；已生成气泡的数值保持固定。

回归场景：59 活力休息一次恢复至 99；睡眠次数用完后，78 活力仍可通过一次合法饮水恢复至 90。每日两次休息、四次间隔喂食和十次陪玩后活力可维持 90 以上，开心保持健康但不持续满格；一夜未照顾后开心会降低，成长加成按实际状态计算。四个入口仍共用同一规则，各存档独立保存。
