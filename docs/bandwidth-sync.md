# 减少云端同步流量

- 存档 GET 使用完整响应内容生成的弱 ETag；未变化返回无响应体的 304。响应仍为 private、no-store，验证标记仅留在当前云端客户端内存，不引入共享缓存，不变更存档键或房间。
- 大于 1 KB 的 JSON 按浏览器 Accept-Encoding 协商 gzip。实时 SSE 同样可使用 gzip，每条消息显式 flush，避免小事件被压缩缓冲而延迟。旧客户端和不接受 gzip 的连接保留原始协议。
- 服务端每 15 秒发送轻量 heartbeat。客户端每 20 秒检查连接；心跳正常时不再下载完整快照，连接断开或至少 45 秒没有消息才恢复兜底 GET。心跳版本比本机新时立即补读。
- 隐藏页面暂停兜底读取，保留实时推送与保存队列。回到前台或网络恢复时核对最新快照，并用原操作 ID 继续提交待保存操作；同时发生的补读合并为一个请求。
- 不压缩或修改 GitHub 存档内容，不改变提交确认、幂等记录、伙伴身份或离线队列。Render 向 GitHub 上传存档等服务端外发仍会计入流量，因此单次响应的压缩比例不等于整月账单降幅。

验证覆盖：真实 HTTP 压缩字节/解压内容、ETag 与 CORS、元数据变化、SSE 即时到达和满员通知、十分钟健康连接无重复 GET、断线/失联兜底、后台实时更新、前台恢复、原 ID 重试和销毁后的监听清理。
