# 贝壳小水獭

## 资源与转换

- 已购模型：[Baby Otter Plush — Glossy Studio](https://www.fab.com/listings/633458db-ec38-4a5e-98b1-264bd90acad9)。原模型没有骨骼和动画。
- 原始 `.blend`、Fab 转换的 `.glb` 和绑定工程只保存在忽略的 `artifacts/licensed/baby-otter/`，不作为公开源素材发布。
- 游戏使用 `public/pets/baby-otter-v1/model.glb`：32,000 三角面、22 根有蒙皮权重的骨骼、两侧闭眼形态，贴图缩至 1024 并编码为 WebP，约 1.7 MiB。
- 动作来自项目已购的 [Nekueda Mage Cat](https://www.fab.com/listings/710bc3f3-6bfd-4942-9eea-c7af4901bf03)。转换脚本先采样包括 FBX 辅助节点的世界空间运动，再以猫猫待机首帧为参考，按水獭抱贝壳的坐姿、肢体长度及幅度重定向。不会把猫猫的关节平移直接套到水獭上。
- 9 段动作：Idle、Walk、Run、Attack、Special_Attack、Hurt、Death、Turn_Left、Turn_Right。后两种受伤/装晕动作仍仅供手动选择，不作为睡眠反应。水獭保留贝壳造型，没有猫猫专属的换毛色、衣服、魔杖材质。
- 喂食、摸摸、玩耍、休息继续使用同一套行为控制；眼部使用水獭自身的网格形态，不能直接套用猫猫的眼睛与嘴巴贴图。

## 存档与加载

装扮新增伙伴选择。猫猫沿用原来的四个装扮字段；水獭只增加可选的 `appearance.character: "otter"`。切回猫猫保留此前的四个配色选择。旧存档、待提交操作、房间、成长、金币和待领取气泡不迁移、不重建。

角色选择随既有 `dress` 操作保存和广播，各存档共享同版代码且各自保存选择。预览不写存档，关闭面板恢复已保存角色。模型首次选择时加载，之后在同一渲染器中缓存切换；快速切换采用最后一次选择，迟到的请求不会覆盖新选择。加载失败保留旧角色并允许重试，不会将失败预览提交。

## 重建

在项目根目录准备已购源文件及现有猫猫的游戏 GLB，使用官方 Blender 4.5 LTS：

```sh
node scripts/prepare-otter-motions.mjs
blender --background --factory-startup --disable-autoexec \
  artifacts/licensed/baby-otter/source/sm_plush_baby_otter.blend \
  --python scripts/prepare-baby-otter.py
```

转换输出和动作渲染核对记录位于 `artifacts/licensed/baby-otter/`。自动测试直接加载实际游戏 GLB，检查骨骼、蒙皮权重、九段动作的真实顶点变形、眨眼、切换竞态以及云端重试后保存不重复。浏览器中的完整交互验收需另外记录，不以离线渲染代替。

## 本地反馈修正：尺寸与眼睛

用户反馈水獭偏大且看不见眼睛。原因是按猫猫包含帽子的 3 单位总高缩放了水獭身体，且把猫猫的开心表情直接映射成水獭 100% 闭眼形态，眼部被压进脸部。

水獭显示高度改为 2.15 单位（缩小约 28%），脚底仍对齐原地面。正常、开心、兴奋等表情保持原装眼睛睁开；眨眼、单眼眨眼的形态幅度上限为 0.55，疲倦为 0.2，不再使用会隐藏眼睛的完全塌缩。此修正不更改已购资源或存档。

新增实际 GLB 显示高度、脚底对齐、开心睁眼以及各表情闭眼上限回归断言。相关 38 项测试通过；浏览器视觉效果仍需用户在共享预览核对。
