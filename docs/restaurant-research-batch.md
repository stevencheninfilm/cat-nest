# 十连探索与珍藏装扮即时反馈

- 研发室保留单次探索，并增加十连探索。需要至少 300 灵感，费用和十次单抽相同；首次蛋包饭赠礼、每第十次五枚碎片与现有卡池概率保持不变。
- 十连使用一个 `restaurant-research-draw` 意图，附带 `count:10` 与起始 `draw`。服务端原子提交十次结果，不允许部分扣费或客户端指定结果。重试沿用同一个操作 ID 与起始序号。
- 最新十连保存在兼容的可选 `research.lastBatch` 回执中，包含起始序号及十张卡；后续单抽替换该回执。手账、翻牌和刷新读取同一份已确认结果，不再次随机或扣费。
- 十连动画先汇聚灵感，再按 0.1 秒间隔逐张翻开十张卡。动画事件不参与存档或按钮解锁；关闭、减少动态效果和后台挂起不会丢结果。超过四秒无回执时沿用“先去经营 / 继续等待”的选择。
- 珍藏装扮接入现有持久队列的确定性即时预览：点击后立即扣除本地可用金鱼干、选中并摆放；离线保留，恢复后重试，明确业务拒绝才回退。服务端仍验证等级、费用和所有权。
- 公开 test 的研发预览终端可准备 600 测试灵感，方便验证两次十连。该测试意图仅由浏览器演示适配器接收，正式服务端不接收测试命令。
