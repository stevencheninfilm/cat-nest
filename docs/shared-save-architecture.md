# 单应用、多存档

2026-10-15：按用户要求，所有线上存档使用同一版应用，以原 `/test/` 已上线的较新前端统一功能。不再让演示快照与正式应用分叉。此前正式应用从 `src/` 构建，而 `/test/` 从冻结的 `demo/app/` 单独构建，因此出现双人照顾、表情、24 只图鉴等功能差异。

## 运行结构

`config/homes.json` 是存档入口配置；同一 `src/entry.js` 解析网址、初始化存档适配器，再加载唯一的 `src/main.js`。所有入口使用同一组构建后的 JS、CSS、图鉴和授权模型。可选调试控制台是工具，不是第二套游戏。

| 入口 | 存档来源 | 浏览器数据 |
| --- | --- | --- |
| `/steven/` | 原 `/api/couple/home`，不复制或重建 | 保留原 `catnest.*`、`catcourt.*` 键 |
| `/evian/` | 原固定房间 `6858d44c3a9ce3b77ea7c5334b4acd02` | 保留 `evian:` 前缀；判官会话和草稿现在也隔离 |
| `/test/` | 同版 reducer 的独立测试数据、模拟伙伴和预设判词 | 当前页面内存，刷新重置，仅指引已读状态持久化 |

公共 `/cat-nest/` 继续跳转 `/test/`。不增加密码或登录。未知路径显示未找到，不连接 Steven，不创建或重置房间。正式存档的 URL 仍为既有访问方式，本次不改变其授权模型。

`app-runtime.js` 统一注入本机存储、会话存储、HTTP 与 SSE。应用缓存、身份、食物选择、待提交队列、伙伴已读位置、判官会话和草稿都在所选存档上下文内。Steven 原缓存和未确认操作、Evian 原前缀保持兼容；旧浏览器原始键不批量搬迁或清理。历史 Evian 判官会话如曾写入未隔离全局键，不自动复制到新空间，以免把其他小窝的角色凭据带入；旧全局记录仍保留。

## 规则与兼容

统一保留已上线测试前端的双人照顾、表情、24 猫图鉴和状态平衡：喂食每日共用 10 次额度，状态每小时下降 1 点，较低互动消耗。后端引用同一 `src/state.js` 和验证模块。旧版 1 存档、成长、日记、装扮、食物、图鉴已入住记录和永久领取凭据保持兼容；仅在正常操作时按新规则计算后续状态，不通过发布重建存档。共同纪念独立验证并允许长期保留，不受普通房间字段大小限制。图鉴邀请验证使用规范化的旧成就快照。

## 增加一个存档

1. 通过现有受控维护流程建立一个新的独立云端房间，保存返回的固定 roomId。不要把旧小窝复制成新用户存档，也不要在页面加载时建房。
2. 在 `config/homes.json` 增加 `{id:"new-friends",label:"新朋友",source:"room",roomId:"32位小写十六进制房间号",storagePrefix:"new-friends:"}`。
3. 运行一次完整测试和构建。入口目录自动生成，校验会拒绝重复房间、重复缓存空间或保留路径。
4. 发布一份共用版本即可，所有已有存档同步更新；不需要逐个复制代码或分别部署。新增网址从 `/cat-nest/new-friends/` 访问。

## 发布约束

- `npm run build` 只有一个 Vite 构建，自动生成所有入口和 `version.json`。
- `verify-shared-build.mjs` 检查每个入口 HTML 完全一致且无独立资源副本，CI 不再运行第二次演示构建。
- 共用功能只验收一次；自动化参数化覆盖每个存档的绑定、缓存、队列和会话隔离。线上核对入口引用同一发布 SHA 和同一资源，不能省略数据隔离检查。
- 后端与 Pages 按准确同一提交依次发布；不发布共享目录未完成修改。
- 本地仍使用 5174 共享预览，离线快照只运行测试和构建。
