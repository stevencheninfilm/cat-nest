# 猫猫游戏屋

首页左侧「逗猫」下方的猫耳手柄「小游戏」进入游戏屋。游戏屋使用四列圆角封面网格，每个入口依次显示封面、名称和「开始玩」。点击游戏后进入模式选择，再选择「单人挑战」「对战电脑」或「双人联机」。两台手机打开同一个网站，分别选择男方和女方。一人发起双人联机，另一人查看邀请并加入。网站共用现有情侣小窝；同一身份不会占用两个玩家席位。

六款游戏都提供「单人挑战」「对战电脑」「双人联机」。单人挑战和对战电脑不需要另一位猫友在线，点击即可开局。双人邀请按钮为「双人联机」。六个封面由内置 imagegen 生成，256px WebP 在 `public/assets/minigames/covers/`；提示词和生成来源保存在 `docs/assets/minigames-covers-v1.json`。

- 石头剪刀布：先得到两胜结束。平手重来，最多二十轮后按比分结算。双方出手后才揭晓，出手后不能更改。
- 猫猫翻牌：十六张、八对猫猫。配对成功继续翻；不同的两张至少展示 1.2 秒，点击收起后换人。八对找齐按配对数量结算，也可单人挑战。
- 五子棋：十五乘十五，黑棋先行，无禁手，五子或以上相连获胜，满盘平局。点选格子后点击「确认落子」，降低手机误触。
- 井字棋：三乘三，叉叉先行，横竖斜连成三个获胜，满盘平局。选择位置后确认放棋子。
- 四子棋：六行七列，珊瑚棋先行，棋子落到所选列最下方空位，横竖斜连成四个获胜，满盘平局。选择列后确认落子。
- 猜数字：服务端随机选取 1–100 的秘密数字。双方轮流猜测，根据偏大或偏小提示收窄范围，先猜中获胜；最多二十次未猜中则平局。已排除范围不能重复猜测。

## 单人和电脑模式

- 单人猜拳：根据显示的提示手势选出克制手势，共三题。每题给出正确答案，完成三题结算。
- 单人翻牌：找齐八对猫猫。
- 单人五子棋：三关“一手成五”挑战，分别练习横线、竖线和斜线。每关选择一次位置，错误时用绿色圆圈展示能成五的位置，完成三关结算。
- 电脑猜拳：电脑在每轮开始时就锁定随机手势，直到玩家出手才揭晓；不根据玩家已经提交的选择调整答案。
- 电脑翻牌：双方轮流找配对，配对成功继续翻。电脑只使用已翻开卡片的记忆，不读取暗牌选择；电脑依次翻开两张，配错后自动换回玩家。
- 电脑五子棋：电脑先寻找立即成五的位置，再阻挡玩家立即成五的位置，其余按棋形和中心位置选择合法落子。电脑回合自动执行，玩家不需要代下白棋。
- 单人井字棋、四子棋：三关“一手连线”挑战，分别练习横线、竖线和斜线。每关选择一次位置，绿色标记展示正确位置，完成三关结算。
- 电脑井字棋：先取胜、再阻挡，其他情况完整搜索剩余棋局，最优对局为平局。
- 电脑四子棋：先取胜、再阻挡，其余搜索后续三层落子并评估连线和中心列。
- 单人猜数字：七次机会根据大小提示找到答案，七次结束后揭晓并结算；使用范围中点策略总能在七次内找到。
- 电脑猜数字：只根据双方公开的大小提示和范围选择中点，不读取服务端隐藏答案。

电脑采用内置算法，不调用外部 AI 服务。电脑身份不能由客户端认领；只有本局玩家可以推进自动回合，服务器检查回合编号和展示等待时间。自动回合也沿用存档、SSE 和重复请求保护。关闭弹窗时保存当前回合，再次进入后继续电脑行动。

## 成长奖励

猜拳、井字棋和猜数字基础 5 点；翻牌、五子棋和四子棋基础 10 点。单人挑战和对战电脑都只发基础奖励。双人联机完成额外 5 点，因此前一组双人每局 10 点，后一组双人每局 15 点。电脑不计入双人奖励。答题表现、输赢都不影响完成奖励；每局只向共享小窝生成一颗气泡。

小窝每天最多从小游戏获得 50 点成长，北京时间（UTC+8）00:00 重置。在额度只剩 5 点时，本局发 5 点；达到上限仍可继续玩。气泡领取时才计入经验，旧气泡不会因跨日而过期或挤占次日额度。小游戏固定奖励不叠加照顾状态倍率，也不增加照顾次数、亲密度或图鉴照顾计数。取消邀请和中途结束没有奖励。

## 保存与同步

正式环境沿用宠物 API 和 GitHub 云存档。客户端只发送开局、加入、出手、翻牌、落子、数字猜测、换回合和取消操作，不可提交胜负或任意经验值。服务端判断回合和终局，完成 GitHub 写入后才回复并广播 SSE。猜拳未揭晓的手势、未翻开的牌序和猜数字答案仅留在服务端存档；HTTP 响应、轮询及 SSE 不包含这些秘密，动作事件也不带出手内容。猜数字只有结束时才向双方显示答案。

每次落子带当前回合编号；旧操作、非玩家操作和已结束对局不能再改变结果。新开局必须引用当前上一局 ID，已结算的奖励回执也阻止同编号重开。重试和同时操作沿用房间队列及 GitHub SHA 并发校验；同一气泡由两人同时领取也只计入一次。

对局随存档保留，刷新或短暂断线后重新连接即可继续。只有明确结束才取消游戏，关闭游戏弹窗不取消。若一位玩家离开，另一位可结束本局重新邀请。

## 本地预览与发布

没有设置 `VITE_API_URL` 时，Vite 的现有预览进程提供本地 HTTP/SSE 和系统临时目录中按项目隔离的文件存档。界面明确标注「本地联机预览」，不写正式 GitHub 小窝；不会触发源代码热更新。旧 `.cat-preview/home.json` 会自动迁入，已迁入的进度不被旧文件覆盖。所有聊天仍共用 `http://127.0.0.1:5174/`，没有新增预览监听器或端口。两个预览标签分别选择不同身份即可测试联机。

生产构建不启用本地预览存储。发布必须同时更新前端和宠物 API；仅更新静态前端时，旧 API 会拒绝新增游戏动作。延续现有 `VITE_API_URL`、GitHub 存档配置与 SSE，不需要新增外部服务或付费游戏插件。

验证包括六个游戏的终局、回合校验、隐藏数据、失败保存、并发出手、刷新读取、奖励领取、每日额度、跨日和时钟回退；也覆盖全部单人/电脑模式、不偷看暗牌和隐藏数字、猜拳预先锁定、棋类胜负优先策略、井字棋全部人类合法路径不输、四子棋重力与满列拒绝、电脑回合重试及三关挑战。HTTP/SSE 测试仅模拟存档服务，不修改正式小窝。真实两台手机及生产部署需在上线时验收。
